# Reproducing the Phase 10 experiment

Use the frozen source manifests and baseline commit in `PLAN.json`. The implementation diff includes the candidate font settings, observation-only harness option and new font regressions. All measured application sources and collector hashes are verified in `EVIDENCE.json`.

1. Use a managed local checkout and the existing reserved disposable onboarding fixture (`scripts/run-onboarding-e2e.cjs --keep`). This performs normal verified signup/TOTP, migrations and provisioning checks. Never use a production project or application environment file. Keep private fixture/config files outside the repository.
2. At the baseline sources, freeze `.next-publish` into a private `baseline` snapshot. Apply the candidate, run the recorded checks, build and freeze a `candidate` snapshot. The lifecycle helper reads a mode-600 `/tmp/outclass-phase10-builds-path` marker pointing to a mode-700 directory beneath the system temporary directory with prefix `outclass-phase10-builds-`. It only operates on the reserved loopback fixture and named snapshots.
3. After QA, seed independent measured actors/clubs using `scripts/navigation-audit.cjs --seed` and enrich with `scripts/pipeline-scale-fixture.cjs` at 1000 and 5000 applicants. Save their private navigation fixture JSON as `fixture-1000.json` and `fixture-5000.json` in that snapshot directory. Reset the private fixture/enrichment marker between independent seeds. Do not print credentials or applicant responses.
4. Run `scripts/navigation-phase10-study.cjs --profile=local`, then `--profile=constrained`, under a temporary `caffeinate -dimsu` assertion with the lid open and sufficient power. Each output directory must be new. The collector enforces the declared BA/AB blocks, warmups, sample counts and frozen build switches.
5. Run `analysis/audit-power.py` on each completed profile directory. Retain and exclude an entire sleep-interrupted collection. Never replace individual slow rows. A user-interrupted partial collection also remains separate; this experiment retains both exclusions.
6. Run `analysis/summarize.py` and `analysis/report.py` for derived comparisons and the report. All warmups and raw errors remain in the profile directories. Initial source navigation and subsequent destination click are separate clocks; pending snapshots do not prove eventual transport completion.
7. Before deleting the private fixture, run `analysis/scan-private-fixture-values.py`. Run `analysis/cleanup.py` only after the scan passes. It removes the owned app/project/volumes/private snapshots, restores the prior inactive fixture directory and final candidate build, and verifies unrelated local services/checkouts. Finally run `analysis/finalize-evidence.py` and verify `SHA256SUMS` after committing.

The retained raw observations can be summarized without a live database. The accepted runs reuse identical builds and cohorts after resumption, with unchanged local connection/public-key values; `RESUMPTION.json` records those checks. No production configuration, schema/index, dependency, security policy or publication step is part of this experiment.
