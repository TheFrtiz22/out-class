Use the reserved disposable loopback fixture, never an application `.env` or hosted database. This experiment uses the existing project migrations and normal verified signup/TOTP fixture provisioner. It does not change security policy, database configuration, schema, indexes or dependencies.

1. Start at baseline `2c95b4dec8fa218274c37f9dd406a090c37e58e0` and preserve subsequent changes. Record unrelated container states and the original checkout; reserve app3107, Auth55321 and database55322. Move any inactive fixture directory aside and record its path privately before provisioning a new owned fixture.
2. Freeze the baseline production build, apply the application diff, run the recorded checks, and freeze the candidate. `navigation-phase11-local.cjs` reads a mode600 `/tmp/outclass-phase11-builds-path` marker pointing to a mode700 system temporary directory prefixed `outclass-phase11-builds-`. It accepts only named snapshots and guards the app listener's PID and checkout.
3. The five new acceptance tests use the candidate build. Deliberately held chunk responses exist only in those regression tests. The separately recorded 16-outcome pilot validates feature selectors and transport, and is excluded whole from performance comparisons.
4. After QA, independently seed the existing synthetic 1,000 and 5,000 applicant cohorts; clear only the owned navigation-fixture and phase3-enriched-count markers between seeds. Save each fixture descriptor privately as `fixture-1000.json` / `fixture-5000.json`. Both builds reuse the exact same cohorts.
5. Run `node scripts/navigation-phase11-study.cjs --profile=local`, then `--profile=constrained`, with the lid open and adequate power under a temporary `caffeinate -dimsu` assertion. New output directories are required. `PLAN.json` declares BA/AB ordering, warmups, counts, readiness and extra feature paths. No product or collector edits, builds or tests compete with collection.
6. Run `python3 docs/performance/phase11/analysis/audit-power.py docs/performance/phase11/local` and the same for constrained. Retain and exclude a whole interrupted collection rather than replacing individual slow rows. Collectors retain failed/pending transports and all planned warmups.
7. Derive comparisons with `analysis/summarize.py` and the report with `analysis/report.py` from complete raw observations. The extra feature series is separate from existing list/detail navigation. Source+click is a per-row sum of two useful-content waits, excluding bounded drains, warm visits and navigation preparation; it is not an uninterrupted elapsed clock or a sum of percentiles.
8. Retain sanitized test logs, exact source/build manifests, implementation diff, every regression, request/server/byte observations and limits. Run the known private-value scan while private fixtures exist, then remove only the owned services/volumes/configs/build snapshots and restore the prior inactive fixture directory. Recheck source hashes, unrelated services, original checkout and main.
9. Run `analysis/finalize-evidence.py` after all artifacts are final. Verify the implementation diff reverses cleanly and all evidence checksums. Commit locally; publication is outside this phase.

A fresh authorized fixture is necessary for rerunning live checks. Committed observations can be analyzed without a live database. These loopback results do not establish hosted or multi-user performance.
