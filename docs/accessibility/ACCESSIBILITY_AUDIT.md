# OutClass accessibility engineering audit

Testing date: **2026-10-20**; final evidence review: **2026-10-21** (America/New_York). Branch: `accessibility/wcag22-audit`. Base: `7ad83d46a3d533b54b9503dd25f7793e5dbb1881`, a clean `main` checkout when work began. No production data, production authentication settings, schema source, deployment or merge was changed. Existing migrations and test-only Auth settings were used solely in a disposable localhost test stack.

This is a technical audit and remediation record, **not certification or a legal determination**. Release recommendation: **Not ready**, because essential human assistive-technology, zoom and remaining complete-workflow checks below are pending. A clean automated sample cannot establish whole-platform WCAG conformance.

## Remediation outcome

Implemented **22 remediation items: 2 P1, 17 P2 and 3 P3**. No P0 was established in the tested scope. The default validation suite passes with its explicit environment-dependent skips; accessibility commands cover public/component states and real signed-in student, owner and administrator pages. Full actual results and scanner review items are in EVIDENCE.md. These are implemented fixes and sampled verification, not proof of whole-platform conformance.

The matrix contains **1 verified pass, 7 not-applicable criteria with justification and 47 not-yet-tested at platform scope**, with no unresolved verified scanner failure in the tested states. Real local signup/verification/ownership and application submission evidence does not remove the need for complete human AT and remaining workflow checks.

## Baseline and method

The official [WCAG 2.2 Recommendation](https://www.w3.org/TR/WCAG22/) governs the matrix. Tests include all axe WCAG 2.0/2.1 A/AA and 2.2 AA tags, without rule exclusions. Source analysis and real-component browser fixtures supplement axe. `incomplete` checks remain in raw reports for human review.

The production homepage was inspected read-only at `https://www.out-class.net/`; Chromium found zero axe violations in that sampled state. This did **not** establish that signup, authenticated tasks, responsive layouts or assistive technology worked. Production does not expose a source SHA in the inspected response, so its deployment is not asserted to match the checkout. `evidence/production-baseline.json` records the URL, timestamp, title and raw scanner results. Before screenshots are retained alongside it. `evidence/local-baseline.json` describes the checkout sample; several initial component fixes had already been made when this local image was captured.

Later browser tests found real contrast and label-in-name failures outside that homepage sample. Source review also identified broken grid metadata, keyboard upload activation, nested audience controls, missing visible success feedback and focus loss following booking actions. See [the remediation register](ACCESSIBILITY_REMEDIATION.md).

## Coverage and limitations

[ROUTE_INVENTORY.md](ROUTE_INVENTORY.md) enumerates every App Router page; [COVERAGE.csv](COVERAGE.csv) inventories all pages and TSX components and source-detected states. This inventory is not a claim that every state was exercised. The browser suite uses actual shared components and actual public routes. The fast student, leader and administrator component fixtures have fictional identities and in-memory action responses; they do not verify server behavior. A separate reserved localhost Supabase runner subsequently provisioned real isolated accounts and passed 38 existing Auth/MFA/HTTP/PostgreSQL/onboarding checks. Additional signed-in axe tests sample real student, owner and elevated-administrator pages; their exact results are in EVIDENCE.md. These samples still do not verify every complete workflow or assistive-technology behavior. The application currently declares a light color scheme; dark utility variants are not an independently verified supported theme. Custom club colors still need rendered contrast review.

## Evidence and release decision

Executed commands and totals are in [EVIDENCE.md](EVIDENCE.md). Human screen-reader, browser zoom, clipping, rendered non-text contrast and remaining full authenticated tasks remain pending. CSS text-spacing and 320px tests only detect document overflow; they do not prove absence of clipped text, obstruction, unexpected visual ordering or two-dimensional content problems.

No P0 was established in the sampled scope. This does not establish that no P0 exists. The later real-account suite adds representative desktop/mobile student, leader and administrator coverage and actual application submission/persistence evidence. Open verification gap **TEST-001 (P1 release risk)** still prevents a full-platform conformance claim. Required next steps are executable in [MANUAL_ACCESSIBILITY_TESTS.md](MANUAL_ACCESSIBILITY_TESTS.md). The [public statement](PUBLIC_ACCESSIBILITY_STATEMENT_DRAFT.md) is a draft only and must not be published until explicitly approved and a monitored contact is verified.
