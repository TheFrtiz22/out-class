# Documents and third-party content review

Source review on 2026-10-20. The entries below are technical observations and testing obligations, not completed document/AT acceptance tests. No outbound email was sent and no uploaded user file was modified.

| Content / ownership | Source evidence and existing alternative | Remaining limitation / exact next action |
|---|---|---|
| User-uploaded résumés and PDFs | `interview-resume-viewer.tsx` renders a selectable PDF text layer (`role=document`), labelled page controls, download, rendering errors and general notes when no text exists. Profile/application data also contains structured academic and experience information. `interview-resume-preview.tsx` now offers keyboard expansion. | PDF.js cannot repair the original PDF's tags, reading order or missing text. Image-only files have no OCR. A download is not an accessible equivalent by itself. Use M02/M07 to test tagged/scanned/encrypted examples; arrange a structured text résumé/profile alternative with the applicant when required. |
| Public demo PDFs | `public/demo/sample-resume.pdf` and `sample-scanned-resume.pdf` are application-owned fixtures. | Neither was certified for document accessibility. Review reading order and PDF structure; the scanned example intentionally has text-extraction limitations. Keep the equivalent fictional profile available and do not treat it as proof that arbitrary uploads are accessible. |
| Event posters and flyers | Event detail dialog contains title, schedule, location, capacity, contact and required Description outside the decorative pulled poster. The leader Description field now explicitly asks for all important image-only information and access instructions. Native poster content supplies discovery button names; uploaded poster alt includes event title. | Title-only alt does not describe all arbitrary flyer content. Authors/moderators must check equivalent Description before publication. A dedicated alt-text database field was not introduced because this assignment does not authorize schema changes. Compare actual uploaded image against text with M04/M07. |
| Application attachments | Document-link and PDF-upload controls remain available; help/errors are associated and upload results announced. | The linked document provider controls its viewer and authoring quality. Verify an accessible text/profile alternative and clearly communicate unusable links/files; actual third-party documents were not tested. |
| Transactional/auth/invitation emails | `lib/transactional-email.ts` uses text content, presentation layout tables, labelled HTML CTA links and Outlook VML alternatives; auth templates include plaintext variants. Code expiration and fallback URLs are text. Existing email design tests are part of validation. | Source/test review does not prove Gmail/Outlook/Apple Mail speech, dark-mode color transformation, zoom or image-blocked readability. Run M07 on actually delivered isolated messages; no authentication/email configuration changes were made. |
| Calendar invitations and event export | `lib/ical.ts` exports textual SUMMARY, DESCRIPTION and LOCATION, event URL and actual dates; event detail remains readable before download. Existing tests cover escaping, UTF-8 folding, all-day and DST instants. | Calendar clients control imported reading order, reminders and accessible UI. Import a fictional invitation into two real clients and inspect with AT. |
| Charts/analytics | Shared metric strips and availability coverage expose textual counts; scheduling admin coverage includes data tables. Source inventory includes leader analytics and reports. | Every essential metric/filter needs corresponding text/table access; exact chart colors, pattern dependence and all dynamic chart datasets are **not yet tested**. Inspect each real analytics/report state in M04/M07; do not infer a pass from chart tokens alone. |
| CSV/JSON reports and imports | Import UIs provide file controls and review steps; admin records use tables or structured descriptions. Existing business tests check validation and authorization. | CSV is plain data, not an accessible spreadsheet with reading order guarantees. Verify meaningful exported headers, accessible row-level errors, bulk selection and review/correct safeguards with M06; no real imports were performed. |
| Radix menus/dialogs/selects, Sonner, cmdk and PDF.js | Real shared dialog/select widgets tested in browser; default focus trap/Escape/return exercised. Existing live region/toast and PDF text mechanisms retained. | Upstream library reputation is not acceptance evidence for each caller. Every dialog needs a name, valid description/focus and usable layout. Actual screen reader timing, nested modal interactions and notification repetition require human verification. |
| Embedded audio/video/media | No application-owned audio/video/iframe player was found in app/components/lib inventory. Animated product previews have text summaries and playback controls. | Any newly introduced player requires captions/transcripts/audio-description assessment and keyboard/AT testing; update criteria currently marked not applicable. |

Operational owner must establish a monitored accessibility reporting channel and an assistance process for files and third-party content. Do not publish an unmonitored email address or promise a response time that has not been agreed.
