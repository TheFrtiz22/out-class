  recovery and other templates were outside the targeted update.
- Sending-domain DKIM (`resend._domainkey.updates.out-class.net`) and SPF
  (`send.updates.out-class.net`) TXT records exist. DNS presence does not establish

  was not established, and no Resend API credential was available to query domain
  status or delivery events. The attempted read-only hosted Auth audit query was
  unavailable. No production email was sent to an invented recipient.

## Actual validation

`npm test`: 476 passed, zero failed, two opt-in tests skipped. The separately
invoked `npm run test:onboarding:e2e` passed all 11 real integration tests using
Next production HTTP server actions, Supabase Auth, PostgreSQL and Mailpit.

The dedicated OTP integration test established:

1. Normal signup creates an Auth user with empty `email_confirmed_at`, no session
   and a six-digit email generated by Supabase from the branded template.
2. Password login before confirmation and an incorrect OTP are rejected.
3. After the actual 60-second cooldown, signup resend produces another email.
4. Correct OTP confirms the user, returns a session, and `getUser()` reports the
   confirmation. Reusing the consumed token fails.
5. Profile creation works; subsequent page reload and `/api/users/me` remain
   authenticated. Signing out and signing in with the password succeeds.
6. Existing-account email OTP sends the separate sign-in template and creates
   a session. A missing-account OTP login request creates no user.

Unit regressions verify exact numeric code format, missing/mismatched sessions,
unsafe/unknown provider configuration, ignored obsolete bypass arguments,
provider errors and matching trusted Azure identity evidence. Real expired tokens
were not waited out; Supabase's shared `otp_expired` error mapping was tested.

`npm run test:migrations`: all 21 migrations on fresh and legacy test databases;
43 tables enforce RLS and deny browser-role CRUD. `npm run typecheck` and
`npm run build` passed. Lint passed with zero errors and 31 existing warnings.

No real Microsoft OAuth login or hosted UVA inbox delivery was exercised. Passing
local Auth/SMTP tests is not a claim of production inbox delivery.
