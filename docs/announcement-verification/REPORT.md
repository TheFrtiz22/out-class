## Fixes and regressions

1. **PR #12 failed the production TypeScript build.** Unconditional throws above the old messaging implementations left unreachable code whose optional club ID could not narrow to a required string. Removed the dead implementations, retained rejecting exports for old clients, and replaced the retired messaging component with its unavailable state. The announcement authorization paths and legacy database tables remain intact. A runtime regression proves retired actions never touch Auth/DB/email.
2. **Durable categories were incorrectly mapped to Announcement.** Application updates, tasks, invitations, platform updates, and legacy messages inherited the Announcement label/filter. Added accurate category labels and a regression proving only ANNOUNCEMENT events enter that category while preserving body/read state.
3. **The native Publish confirmation stalled browser automation.** Replaced it with an accessible in-app confirmation and a synchronous submission guard. Browser publication was rerun with a double-click and database counts proved one announcement, one notification, and one delivery.
4. **The existing communications HTTP suite still required direct messaging.** Replaced those obsolete positive messaging scenarios with announcement-focused Auth/HTTP/PostgreSQL tests, negative checks for retired actions, and mocked provider failure/preference scenarios.

No schema or authorization bypass was introduced. Fixture provisioning uses local Auth admin confirmation; it does not prove ownership through a new external verification email. Main publication, notification creation, read persistence, preferences, queue assignment, worker authorization, and provider receipt persistence used normal application paths. Direct fixture writes/time manipulation were limited to initial setup and isolated mocked failure cases.

## Reproduction and limits

`node scripts/prepare-announcement-e2e.cjs` provisions a fresh reserved local fixture, applies authoritative Prisma migrations, and builds the app. Private config/credentials stay outside the repository in the OS temp directory. Existing fixtures are retained for review instead of overwritten. `node scripts/announcement-e2e-control.cjs start` starts it with email disabled; `validate` runs the required checks with isolated connection overrides. Set `OUTCLASS_ANNOUNCEMENT_E2E_CONFIG` to that private config to run `tests/communications-e2e.test.cjs` against the real built application. Every provider call in that test is intercepted; it cannot send real email.
